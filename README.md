# Coast — 차량 AI 상호작용 실험

iPad 참가자용 내비게이션 자극과 PC 진행자용 관리자 화면을 포함한 연구용 웹앱입니다. 현재 화면·서버 버전은 **2.9.9**입니다. package.json의 2.0.0은 초기 패키지 버전입니다.

## 2.9.9 D1 읽기 사용량 절감

- 누적 음원·터치 로그를 훑던 배정표 조회에 종류별 부분 인덱스 3개를 추가합니다. 마이그레이션은 인덱스만 생성하며 배정표·시행·설문·로그를 삭제하거나 수정하지 않습니다. 이전 화면에서도 인덱스가 적용됩니다.
- 다음 시나리오 준비·설문 완료 검증은 해당 배정표와 참가자의 기록만 조회합니다. 참가자 순서와 seed를 유지한 전체 배정을 생성한 뒤 참가자를 선택하므로 기존 조건 배정은 바뀌지 않습니다.
- 관리자 진행 갱신은 선택한 배정표만 조회하고, 최신 표의 중복 갱신을 생략합니다. 다른 배정표는 선택해서 조회할 수 있고 **배정표 다시 불러오기**는 전체 목록을 다시 확인합니다. 처음에는 마지막 실제 시행의 배정표를 우선 선택합니다.
- 준비·진행 중에는 기존 응답 후 150ms 조회를 유지합니다. 종료·중단·초기 대기 중에는 1초로 줄이며 5초 경고·10초 단절 기준은 유지합니다. 업데이트 후 시행 사이에 PC와 iPad를 새로고침하세요.
- 검증: 기존 운영 기록의 로컬 복제본으로 모든 배정표의 조건·진행 결과가 수정 전후 동일한지 대조했습니다. 서버 응답 유실·배정표 실패·자동 복구도 로컬 브라우저에서 확인했습니다. 운영 기록에 테스트 시행을 추가하지 않습니다.
- 인덱스 추가는 이미 사용한 당일 한도를 되돌리지 않습니다. 하루 전체 사용량은 운영 시간·조회 빈도·실험량에 따라 계속 확인해야 합니다.

## 2.9.8 배정표와 진행 버튼 복구

- 다음 시나리오 준비·시행 종료·묶음 설문 완료·배정표 저장은 요청당 최대 4.5초, 전체 최대 14초/3회 범위에서 같은 명령 ID로 결과를 재확인합니다. 음원 진행 명령의 기존 시간 제한은 유지합니다.
- 배정표 조회도 4.5초/3회 재시도합니다. 계속 실패하면 기존 표를 유지하고 최신 진행 상태가 확인될 때까지 다음 준비·설문 완료·수동 선택을 잠급니다. 배정표가 열린 동안 5초 후 다시 조회하며 로그인·권한 오류는 자동 반복하지 않습니다.
- 조회 도중 시행이 바뀌면 오래된 결과를 적용하지 않고 최신 상태로 다시 조회합니다. 동시에 요청한 갱신은 하나의 요청을 공유합니다.
- 서버 명령 저장 성공과 배정표 갱신 성공을 구분해 표시합니다. 배정표 오류·재시도도 연결 진단 로그에 포함합니다.
- 지연 2.8초, 명령 처리 후 응답 유실, 배정표 연속 실패·자동 복구를 로컬 브라우저에서 검증했습니다. 두 시나리오와 묶음 설문을 진행해 시행·종료·설문 기록이 중복되지 않고 다음 순서가 3/16으로 복구되는 것을 확인했습니다. 운영 실험 데이터를 테스트에 추가하지 않았습니다.

## 2.9.7 연결 지연 대응

- 2026-10-13 운영 D1 로그를 읽기 전용으로 확인했습니다. 10월 12일 14:53:19, 16:54:01, 17:00:54(KST)에 명령이 서버에 저장된 뒤 PC 응답 타임아웃으로 재생이 종료됐습니다. 학교망 차단이나 D1 한도 초과가 원인인지는 이 로그만으로 확정할 수 없습니다.
- 명령 응답을 잃으면 같은 이벤트 ID와 기준 상태 번호로 최대 3회, 전체 8초 범위에서 재확인합니다. 이미 처리한 명령은 다시 실행하지 않습니다. 취소된 흐름은 재시도하지 않으며 권한·조건 오류(4xx)는 즉시 표시합니다.
- 상태 조회는 최대 4.5초까지 응답을 기다립니다. 조작 잠금은 연결 확인 지연 5초부터, 재생 중단은 10초부터 적용합니다. 짧은 지연에서는 현재 음원을 유지하고 다음 동작은 연결 확인 후 진행합니다. 화면 이탈·시행 변경·장기 단절 시 중단하는 원칙은 유지합니다.
- 상태 조회 주기는 유지하고 접속 시각 DB 갱신만 기기별 1초 간격으로 제한합니다. iPad 미전송 로그 수가 바뀌면 즉시 갱신합니다. 시행·터치·음원 이벤트는 생략하지 않습니다.
- 관리자 연결 카드에 PC와 iPad의 마지막 연결 확인 시간, PC 왕복 시간, 최근 오류를 표시합니다. **연결 진단 로그 저장**은 서버에 접속할 수 없어도 이 PC에 보관한 최근 100개 오류·재시도·복구 기록을 JSON으로 저장합니다. 인증 토큰과 참가자 ID는 포함하지 않습니다. 전체 실험 이벤트는 기존 **전체 JSON**으로 내보냅니다.
- 로그인 만료를 별도로 표시합니다. 업데이트 후 시행 사이에 PC와 iPad를 모두 새로고침하고 PC 음원을 다시 선택하세요. 실제 학교망/iPad 환경의 장시간 안정성은 현장 검증이 필요합니다.

## 포함된 기능

- 참가자 `/`: 실제 해안 지도, 터치 이동·확대, 고정 경로·방향 화살표, AI 상태별 애니메이션.
- 진행자 `/admin`: 연결 코드, 8조건 선택, 시행 준비·시작·종료·중단, Cue·화면 상태 제어.
- PC 로컬 음원 재생 및 참가자 터치/진행자 확인에 따른 후속 재생.
- Williams 라틴스퀘어 8조건 묶음 × 2시나리오 배정: 장소(식당·카페) 1회 + 정보(날씨·도로) 1회 후 묶음 설문 완료 확인. 이전 배정표는 원래 방식으로 보존.
- 시행·이벤트 저장, 한국어 로그 요약, CSV·JSON 내보내기, 확인 후 기록 초기화.
- Sites Worker API, D1 스키마·마이그레이션, 로컬 SQLite 서버, 회귀 테스트.

실제 AI, 음성 인식·녹음, GPS 추적, Slow Roads 연동은 없습니다. Slow Roads는 별도로 TV에 표시하며 지도 경로와 화살표는 고정된 시각 자극입니다.

## 다른 PC에서 실행

Node.js **24 이상**, npm, Git이 필요합니다. 저장소를 복제한 폴더에서 실행합니다.

```sh
npm ci
npm test
npm run build
npm start
```

- 참가자: http://127.0.0.1:4173/
- 진행자: http://127.0.0.1:4173/admin
- 종료: 실행한 터미널에서 Ctrl+C.

로컬 서버는 `127.0.0.1`에만 바인딩하며 한 PC의 두 브라우저 탭으로 기능을 확인하는 용도입니다. iPad에서는 이 주소에 접속할 수 없습니다. 로컬 API는 테스트 소유자 계정을 사용하므로 외부 공개 서버로 실행하지 마세요. 개발 DB는 `.sites-runtime/coast.sqlite`에 생성되며 Git에서 제외됩니다.

## 실험 진행

1. 관리자에서 연결 코드를 생성하고 iPad 준비 모드 설정에서 입력합니다.
2. 익명 참가자 ID, 관계, 개입 방식, 시나리오를 선택하거나 저장한 배정표에서 불러옵니다.
3. 시행 준비 후 iPad 적용 확인을 기다리고 시행 시작을 누릅니다.
4. PC에서 대화·최종 답변 음원을 선택합니다. Suggestion에는 제안 음원도 필요합니다.
5. **동승자 대화 재생 · 자동 진행**을 클릭합니다. Space는 초기 재생이 아닌 응답 대기 중 확인 키입니다.
6. 답변 재생 후 진행자가 시행 종료 또는 중단을 선택합니다. 로그 저장 대기가 0건인지 확인합니다.

| 조건 | Idle 준비 상태 이후 |
|---|---|
| Reactive | Idle 대화 → 아이콘 터치 → Listening 요청 발화 → 진행자 확인 → Thinking → Speaking 답변 → Idle |
| Cue | Listening 대화 → Twinkle → 아이콘 터치 → Thinking → Speaking 답변 → Idle |
| Suggestion | Listening 대화 → Thinking → Speaking 제안 → Listening 응답 → 진행자 확인 → Thinking → Speaking 답변 → Idle |
| Direct | Listening 대화 → Thinking → Speaking 답변 → Idle |

아이콘은 모든 조건에서 상시 표시하며 숨김 상태는 없습니다. Cue만 Twinkle 도움 제안 상태를 사용합니다. 초반 대화는 PC 재생 시작 시점에 맞춰 Listening 전환을 요청하며, Thinking 대기는 기본 0.5초입니다. 상태별 로그 업로드를 기다리며 대기 시간을 늘리지 않습니다. 소리는 PC에서 나므로 OS 출력 장치를 TV/HDMI로 지정합니다. 음원은 업로드되지 않으며 새로고침이나 조건 변경 시 다시 선택해야 합니다.

모든 AI 발화 직전에 공통 0.5초 띠링 알림음을 PC에서 자동 재생한 뒤 0.18초 쉬고 발화합니다. 2.7.2에서는 이전 알림음보다 진폭을 약 3dB 높이고 잔향 감쇠를 늘렸습니다. Suggestion은 제안과 최종 답변 앞에 각각 한 번, 나머지 조건은 최종 답변 앞에 한 번입니다. Thinking 대기 후 Speaking 전환을 요청하고 알림음→짧은 간격→음성 순서로 재생합니다. 동승자 대화에는 알림음을 붙이지 않습니다.

아이콘은 기본 144px로 확대하고 상태 이름을 표시합니다. Reactive·Cue의 답변은 현재 시행·재생 실행·아이콘에 연결된 참가자 터치 기록이 있어야 시작합니다. Reactive는 터치 후 진행자의 발화 완료 확인도 필요합니다.

## 배포·데이터·측정 범위

Cloudflare 이전 및 자동 배포 설정은 [CLOUDFLARE.md](CLOUDFLARE.md)를 따릅니다. 현재 이 저장소는 Cloudflare Workers Builds에 연결되어 `main` push에 따른 자동 배포가 활성화되어 있습니다.


`npm run build`는 Cloudflare Worker를 `dist/cloudflare`에 검증 빌드합니다. 기존 Sites 번들은 `npm run build:sites`로 생성합니다. `.openai/hosting.json`은 이전 Site의 연결 정보입니다. 기존 Sites에는 GitHub push만으로 배포되지 않습니다. 현재 운영 중인 Cloudflare 사이트에 `main` push로 자동 배포합니다.
GitHub Actions는 테스트와 두 플랫폼의 빌드 아티팩트를 검증·보관합니다. [CI·배포 안내](docs/CI-AND-DEPLOYMENT.md)를 참고하세요.


운영 DB, 로컬 DB, 참가자 로그 내보내기, 선택한 음원, 로그인 정보는 저장소에 포함하지 않습니다. 음원은 별도로 준비합니다. 스키마 변경은 `npm run db:generate`로 새 마이그레이션을 생성하며 이미 배포된 마이그레이션은 수정하지 않습니다.

Cue 반응시간은 같은 iPad의 표시 적용 기록 → 첫 터치입니다. 진행자 확인 간격은 참가자의 순수 발화 반응시간이 아니며 브라우저 재생 이벤트는 물리적 TV 음향 시작 시각이 아닙니다. 실제 iPad Safari·TV·장시간 실험은 현장 파일럿이 필요합니다.

## 2.9.6 배정표 수동 선택

새 배정은 친구(FR)·직장 관계(BU) × RA/PC/PS/PD의 8조건입니다. 참가자당 16시나리오·8회 묶음 설문, 식당·카페·날씨·도로 각 4회입니다. 식별자는 `FR-restaurant`, `BU-weather`처럼 관계-시나리오만 포함합니다.

각 행의 선택 준비/재시행 준비로 순서를 직접 선택할 수 있습니다. 현재 시행을 종료·중단하고 연결을 복구한 뒤 준비하세요. 이전 시행은 보존하고 새 시행 번호 및 수동 선택 사유를 기록합니다. 자동 진행은 첫 미완료 묶음부터 이어지며 완료된 설문은 다시 요구하지 않습니다. 재시행이 기존 기록의 무효화나 설문 재수집을 뜻하지는 않습니다. 기존 12조건 배정표를 새 설계로 바꾸려면 새 배정표를 저장하세요. 기본 인원 16은 균형 주기 예시입니다.

## 2.9.6 네 점 AI와 이동 경로

2026-10-07: PC 자동 재생의 Proactive Cue는 서버가 정한 공통 시작 시각(명령 처리 후 1.2초)에 iPad의 정보 제공 가능(Twinkle) 표시와 기존 0.5초 알림음을 예약한다. 각 기기는 서버 응답 시각·요청 왕복 시간을 이용해 로컬 시계를 보정한다. 화면 적용 확인 왕복을 기다린 뒤 소리를 내던 지연을 제거했으며, 물리적 디스플레이·TV 음향 출력 지연까지 보장하는 동기화는 아니다. Cue 신호는 시각·청각 신호를 함께 사용한다. 참가자가 바로 터치해도 이 알림음이 끝난 뒤 답변 절차로 이어지며, 최종 발화 전 알림음도 유지한다. 재생 로그의 `cue_chime`은 정보 제공 가능 알림음이고 `chime`은 발화 전 알림음이다. Cue 반응시간은 기존처럼 iPad 표시→터치로 측정하며 음향 시작 기준으로 바꾸지 않는다.

관리자 화면의 관계 표기는 FR·BU, 시나리오 표기는 restaurant·cafe·weather·road로 줄인다. 저장된 배정·시행의 기존 관계 접두사 식별자는 이력 호환성을 위해 유지하고 표시할 때만 간략화한다.

참가자와 관리자는 `dot-ai.js/css`를 공유한다. Idle 네 점 정지, Listening 순차 바운스, Thinking 시계방향 회전, Speaking 두꺼운 막대 높이 변화. Twinkle은 같은 회전과 AI 패널 테두리 발광, “원하는 정보를 드릴 수 있어요!” 말풍선이다. WebGL 구체는 이전 시안에만 보존한다.

지도에는 Cabrillo Highway에서 Santa Cruz까지 저장된 약 106.5km 경로 전체를 표시하며 화살표는 기존 출발점에서 북쪽으로 초당 6m 이동한다. 출발점 이후에도 100km 이상 이어져 4시간 넘게 주행할 수 있다. OSRM/OpenStreetMap에서 받은 실제 도로 좌표를 파일로 저장하여 실험 중 경로 서비스에 요청하지 않는다. 끝에서는 정지하고, 초기화 및 새 시행 준비 시 같은 위치로 복귀한다. 숨겨진 탭이나 동작 줄이기 설정에서는 이동을 멈춘다. Speaking은 음성 진폭 분석이 아닌 상태 기반 애니메이션이다.

지도 카메라는 화살표를 따라가며 진행 방향에 맞춰 부드럽게 회전한다. 기본 기울기는 55도, 줌은 15.5(기본 축척 막대 100m)이며 화살표를 지도 높이의 68% 위치에 유지해 전방 경로를 보여준다. 화살표는 화면 기준으로 위를 향하고 소수점 픽셀 위치를 유지하여 카메라 회전과 픽셀 반올림에 따른 흔들림을 방지한다. 확대·축소는 추적 중에도 유지되며 홈/새 시행 준비는 출발 위치와 기본 100m 시점으로 복귀한다. 자동 추적과 충돌하지 않도록 지도 드래그 이동은 사용하지 않는다. 지형·건물의 3D 모델을 추가한 것이 아니라 기존 지도를 원근 시점으로 표시한다.
